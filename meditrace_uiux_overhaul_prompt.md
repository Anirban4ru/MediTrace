# MediTrace — Complete UI/UX Overhaul Prompt (for Antigravity AI IDE)

---

## ROLE

You are a senior product designer and senior frontend engineer working inside the `MediTrace` Next.js repository. You are performing a **full visual redesign** of the application. This is a *skin transplant*, not a rebuild: every route, API call, data model, auth flow, smart-contract integration, IoT telemetry pipeline, and piece of business logic must continue to work exactly as it does today. Only the presentation layer changes.

Before writing any code, do the following reconnaissance:

1. Open `https://meditraceorg.vercel.app/` and screenshot every major screen (landing/marketing page, login/auth, dashboard, track/trace view, analytics, settings, any modals/widgets). Note current component boundaries — you'll be restyling these, not rebuilding them from scratch, so understand what DOM structure already exists.
2. Open `https://www.sharplink.com/` and screenshot the same set of comparable screens (home, about, investors/dashboard-style page, news/listing page, FAQ/accordion, footer). Study it as a **reference for tone and craft**, not as a template to literally copy — SharpLink is a fintech/treasury site and MediTrace is a pharmaceutical supply-chain integrity platform. You are borrowing its *design maturity*, not its industry, copy, or literal content.
3. Read `ui_ux_details.md` in the repo root (or wherever it lives) — it documents the *current* design system (brutalist + glassmorphic, hard black borders, `#000` ink, sharp corners, Inter + JetBrains Mono). Treat it as the "before" spec you are replacing, and as a map of every CSS primitive/class you need to find and retire (`.brutal-border`, `.brutal-shadow`, `.brutal-card`, `.brutal-press`, `.glass`, `.glass-strong`, `.grid-canvas`, `.scanline`, `.animate-in`, `.animate-blur-in`, `.no-scrollbar`, and their usages across the codebase).

## THE BRIEF

Take MediTrace from its current **brutalist + glassmorphic engineering-blueprint look** to a **premium, institutional-grade editorial aesthetic** in the spirit of SharpLink — restrained, confident, quiet-luxury fintech/enterprise design. Same information, same features, same user flows. Completely different visual language.

The result must read as **designed by a skilled human studio**, not generated by an AI template. That means:

- No generic "AI slop" visual tropes: no purple-to-blue radial gradient blobs floating behind headlines, no glossy 3D glass spheres, no overused neon glow-on-hover, no stock-icon-in-a-circle grids, no emoji used as icons, no Inter-at-default-weights-everywhere-with-no-hierarchy.
- No copy-paste from SharpLink's brand (no NASDAQ/SBET/ETH references, no borrowed logos, no borrowed copy). Borrow *craft decisions*: pacing, whitespace discipline, restrained motion, typographic confidence, cinematic hero treatment, editorial section rhythm, understated color use, accordion/FAQ polish, footer structure.
- Every visual decision should feel *intentional and specific to MediTrace's domain* (pharmaceutical supply-chain integrity, cold-chain telemetry, blockchain provenance, regulatory trust) rather than a generic dashboard reskin.

## DESIGN DIRECTION TO IMPLEMENT

### 1. Overall philosophy shift
- **From:** hard-edged brutalism (thick black borders, hard drop shadows, 0px radius everywhere) layered with glassmorphism and an engineering-graph-paper background.
- **To:** a dark-first, editorial, institutional aesthetic — generous negative space, quiet confident typography, subtle motion, cinematic full-bleed hero moments, thin hairline dividers instead of heavy borders, soft large-radius cards used sparingly, and color used as signal (status, trust, alert) rather than decoration.
- Keep a *few* brutalist DNA fragments as an intentional signature rather than deleting the whole identity wholesale — e.g., retain sharp corners **only** on data/telemetry chips (hashes, hex, GPS coords) to preserve the "engineering precision" association, while everything else softens. This is what will make it feel like a deliberate evolution rather than a template swap.

### 2. Color system (rebuild `globals.css` tokens + `tailwind.config.ts`)
- Primary surface: move from pure-white canvas to a deep near-black/navy base for marketing and hero surfaces (inspect SharpLink's actual hex via screenshot/inspector for the exact tone — do not guess), with a clean white/light surface reserved for dense data screens (dashboard tables, track/trace detail) where legibility of telemetry data matters more than mood.
- Replace `--danger: #b91c1c` styling context but keep the semantic role (spoilage/alerts) — it should now read as a precise, restrained alert red used sparingly against the dark palette, not a flat brutalist block.
- Introduce one refined accent (cool blue/steel, consistent with the existing `--accent: #102a43` family) used the way SharpLink uses its accent: in thin gradient washes behind hero sections, in link/button states, and in data visualization — never as a background fill on large UI chunks.
- Kill the visible grid-canvas blueprint texture on marketing surfaces; if a texture is kept, make it near-invisible (a faint noise/grain overlay for depth, not a visible ruled grid).

### 3. Typography
- Keep `Inter` for UI and `JetBrains Mono` for data/hashes/telemetry (this split is good and worth preserving — it's legitimately how serious fintech/infra products differentiate human copy from machine data).
- Rebuild the type scale for editorial confidence: larger, tighter-tracked display headings for marketing sections (similar spirit to `.display-heavy`, but pair it with *generous* line-height on body copy instead of applying tight tracking everywhere).
- Establish a clear 4–5 step scale (display / h1 / h2 / body-lg / body / caption-mono) and use it consistently — SharpLink's biggest tell of craft is typographic consistency, not any single font choice.

### 4. Components
- **Cards/widgets:** replace `.brutal-card` (hard border + hard offset shadow) with a quiet card system — hairline 1px border at low opacity, soft ambient shadow, larger corner radius (8–12px) on standard content cards, reserving sharp corners for the mono-data chips as noted above.
- **Buttons:** replace `.brutal-press` translate-and-shrink physical press with a subtler press (slight scale + shadow softening), and add a refined primary/secondary/ghost button hierarchy matching SharpLink's restrained button styling (thin outline secondary buttons, solid but not loud primary buttons).
- **Glass panels:** keep glassmorphism only where it earns its place — e.g., a sticky top nav over a video/image hero — and tone down blur/opacity so it reads premium, not trendy.
- **Navigation (TopBar/Sidebar):** redesign to the editorial nav pattern — logo left, slim horizontal link row, understated auth/role state, and (if a mega-menu or full-screen overlay menu fits the mobile pattern) borrow that interaction, not the visual skin.
- **FAQ/accordion pattern:** if MediTrace has or could use an FAQ/help section, model its interaction and pacing after SharpLink's numbered accordion (numbered items, thin dividers, single-open expand) — reuse the *pattern*, write MediTrace-specific content.
- **Footer:** rebuild as a structured multi-column footer (nav, legal, social) with a hairline top divider and small-caps/mono micro-labels, echoing SharpLink's footer discipline.

### 5. Motion
- Replace `fade-rise`/`blur-in` mount animations with slower, more confident easing (institutional sites move deliberately, not snappy/bouncy). Target ~400–600ms with a custom cubic-bezier, staggered slightly per section as the user scrolls, not simultaneously on load.
- Scroll-triggered reveals for marketing sections (Framer Motion `whileInView`) instead of only on-mount animation.
- Keep the `.scanline` motif *only* if it's repurposed meaningfully (e.g., an active cold-chain telemetry indicator), not as generic background decoration.
- Respect `prefers-reduced-motion` throughout.

### 6. Data visualization surfaces (dashboard, analytics, GPS/map widgets)
- These stay information-dense and light-surfaced for legibility, but should adopt the same hairline-border, generous-padding, restrained-color language as the marketing pages so the whole product feels like one system, not two eras bolted together.
- Recharts/Leaflet/react-globe.gl instances: restyle chart colors, gridlines, and tooltips to match the new muted palette (no bright brutalist primaries).

## WHAT MUST NOT CHANGE

- Routing, page structure, and URL scheme.
- All business logic: auth, blockchain (Arbitrum L2) calls, IoT telemetry ingestion, OpenCV verification flows, role-based access.
- Component data contracts/props — restyle in place; if a component must be split for the new layout, preserve its external API where other code depends on it.
- Actual content meaning (product copy can be *lightly* tightened for the new editorial tone, but claims, data, and functionality descriptions must stay accurate).
- Accessibility: maintain or improve contrast ratios and semantic HTML; the dark theme especially needs contrast-checked text colors.

## EXECUTION PLAN FOR THE AGENT

1. Inventory every usage of the retiring utility classes (`brutal-*`, `glass*`, `grid-canvas`, `scanline`, `animate-in`, `animate-blur-in`) across the codebase before touching `globals.css`, so nothing silently breaks.
2. Rebuild design tokens first: `tailwind.config.ts` (colors, radius, font scale, shadows) and `globals.css` (CSS variables, new utility primitives replacing the retired ones with equivalent hooks so component markup changes stay minimal).
3. Rebuild shared primitives next (Button, Card, Badge/Chip, Nav, Footer, Accordion) since every page composes from these.
4. Then move page-by-page: marketing/landing → auth → dashboard shell → track/trace detail → analytics → settings.
5. After each page, take a screenshot and self-review against the "no AI-slop" checklist above before moving on.
6. Do a final pass for motion consistency, contrast/accessibility, and responsive behavior (mobile nav, mobile hero, mobile data tables).

## ACCEPTANCE CRITERIA

- Visually distinct from the current brutalist/glassmorphic version, with a confident, restrained, premium institutional feel comparable in *quality* (not literal styling) to SharpLink.
- No functional regressions — every existing flow works identically.
- No leftover unused legacy CSS classes.
- Consistent design tokens used everywhere (no one-off inline hex colors).
- Looks and feels like it was art-directed by a human designer with a point of view, not assembled from a component-library default theme.
